# Igris — plan

One line: **Lighthouse for dapp privacy: scan, explain, fix, publish.**

Igris tells dapp developers and users which third parties learn a user's wallet address, and
which third parties learn their IP even without an address.

## The four verbs

1. **SCAN** — load a dapp in headless Chromium with a mock wallet exposing a unique throwaway
   "canary" address. Any captured request containing the canary (in any decodable form) is a
   provable leak. Classify every contacted host (first-party, RPC provider, analytics, error
   monitoring, support chat, wallet-connect relay, IPFS gateway, CDN, unknown).
2. **EXPLAIN** — a transparent 0–100 score; every penalty is an itemized ledger line traceable
   to finding IDs. `igris scan --explain` prints the ledger.
3. **FIX** — `igris fix <path>` patches viem/ethers/wagmi RPC setups to route reads through the
   Ethereum Foundation's Anon-RPC browser harness, then a rescan proves before/after.
4. **PUBLISH** — scan results become Arkiv entities (30-day expiry) written by the scanner's
   wallet. A static web viewer reads them back with filters. An entity is an attestation by its
   scanner address, not a fact.

## Bounty constraints honored structurally

- **No backend we operate**: CLI runs locally, web app is static, registry is Arkiv.
- **No third-party trackers/fonts/CDN assets** in anything we ship; system font stack.
- **MIT**, clone-to-running in <10 minutes, no secrets required for the offline path.
- **Our own tooling is privacy-safe**: scans send nothing by default (stubbed wallet reads);
  the viewer's Arkiv endpoint is user-configurable; trade-offs in docs/METHODOLOGY.md.

## Key design decisions

- **Offline e2e**: Playwright Chromium launches with
  `--host-resolver-rules=MAP *.igris-sink.test 127.0.0.1`, so fixture pages can talk to
  `rpc.igris-sink.test`, `analytics.igris-sink.test`, etc. without DNS or the internet.
- **Mock wallet reads are stubbed by default** (zero balance, fixed block): a scan can never
  leak the canary from the scanner's IP. `--live-reads <url>` opts into real forwarding.
- **`usesAnonRpc` detection** (verified against spec v0.4.0, see docs/ANON_RPC_NOTES.md):
  anonymized traffic deliberately has no stable wire signature, but the harness makes ONE
  non-anonymized bootstrap `eth_call` through the dapp's existing EIP-1193 provider — our mock
  wallet — selecting `workerHash()` / `workerResolvers()` on the specifier contract. We match
  those 4-byte selectors on wallet-routed `eth_call`s.
- **Patcher target API** (verified): `new AnonRpcWorker({ address, preExisting: { rpcProvider } })`,
  then `worker.fetch` as a drop-in fetch — viem `http(url, { fetchFn })`, an ethers
  `FetchRequest.getUrlFunc`, wagmi via its viem transports. The patcher emits one shim module
  per repo and rewires transports to it.
- **Arkiv schema** (`igris.scan.v1`): indexed `hostname`, `score` (i32), `scannedAt` (u64),
  `leakCount`, `thirdPartyCount` (i32), `usesAnonRpc` (bool), plus `leakClasses` (str),
  `scannerVersion`, `reportVersion`, `chainId`, `reportSha256` (str), `summary` (bytes, compact
  JSON, no canary-bearing URLs). 30-day expiry (`ExpirationTime.fromDays(30)`), justification in
  arkiv/schema.md. Viewer trusts entities only by `$owner` (pinned scanner addresses).
